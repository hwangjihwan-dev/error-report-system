# 오류신고 관리 시스템

사용자가 서비스 이용 중 발견한 오류를 신고하고,
관리자가 신고 내용을 확인하여 답변, 반려, 처리상태 변경 및 처리 이력을 관리할 수 있는 웹 애플리케이션입니다.

단순 CRUD 구현을 넘어 실제 운영 서비스를 가정하여
사용자/관리자 권한 분리, 본인 데이터 접근 제한, 첨부파일 관리,
검색·필터·페이징, 반려 처리, 처리 이력 추적, 엑셀 다운로드,
통계 대시보드와 공통 예외 처리를 구현했습니다.

또한 주요 비즈니스 규칙을 서비스 계층에 두고
JUnit 5, Mockito, AssertJ 기반 단위 테스트를 작성하여
답변·반려 상태에 따른 수정/삭제 제한과 처리 이력 저장 로직을 검증했습니다.

## 주요 비즈니스 규칙

### 오류신고 수정 / 삭제

사용자는 본인이 작성한 오류신고만 수정하거나 삭제할 수 있습니다.

다음 조건에서는 수정 / 삭제가 제한됩니다.

- 관리자 답변이 등록된 경우
- 오류신고가 반려된 경우

### 관리자 답변

관리자는 오류신고에 답변을 등록하거나 수정할 수 있으며,
답변과 함께 처리상태를 변경할 수 있습니다.

답변 처리 시 선택 가능한 상태는 다음과 같습니다.

- `RECEIVED` - 접수
- `IN_PROGRESS` - 처리중
- `COMPLETED` - 완료

### 반려 처리

반려는 답변 처리와 분리하여 구현했습니다.

반려 가능한 조건:

- 관리자 답변이 등록되지 않은 오류신고
- 아직 반려되지 않은 오류신고

반려 처리 시 다음 정보를 저장합니다.

- 반려 사유
- 처리 관리자
- 처리 일시
- 처리상태 `REJECTED`

반려된 오류신고는 사용자가 수정하거나 삭제할 수 없습니다.

### 처리 이력

관리자가 다음 작업을 수행할 때 처리 이력을 저장합니다.

- 답변 등록
- 답변 수정
- 반려 처리

처리 이력에는 다음 정보가 저장됩니다.

- 오류신고
- 처리 관리자
- 변경 전 처리상태
- 변경 후 처리상태
- 답변 내용 또는 반려 사유
- 처리 일시
